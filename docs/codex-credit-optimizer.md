# Codex Credit Optimizer Skill

## 目的

CodexデスクトップアプリでのVibeコーディング時に、探索量・ログ量・長時間思考を抑えながら、同人ゲーム開発の品質を維持することが目的です。

## Codexデスクトップアプリでの使い方

作業開始時にリポジトリの状況を短く要約します。

```bash
npm run codex:summary
```

出力と依頼内容をCodexに渡し、関連ファイルだけを調査させます。

## Vibeコーディング時の頼み方

目的、再現手順、変更してよい範囲、変更してはいけない仕様を短く伝えます。

> 釣り結果画面の閉じるボタンがEscapeで動かない。関連箇所だけ調査し、マウス操作と他のミニゲームは変えずに最小修正して。

仕様相談の段階では「まだ修正しない」と明記し、可否と影響範囲だけを確認します。

## 長いログの要約

ビルドログをそのまま貼らず、重要エラーと前後2行に圧縮します。

```bash
npm run build 2>&1 | npm run codex:error
```

## 農場ゲーム開発で守るルール

- 借金、AP、難易度、栽培、採掘、釣り、伐採、戦闘などの数値は勝手に大きく変えない。
- 仕様を変える場合は変更前後を示し、プレイ体験への影響を確認する。
- ポップアップやイベント中は最前面表示、重なり防止、背後操作ロック、フォーカス復帰を確認する。
- Enter / Space / Escape / 矢印 / WASD / クリックを、必要な画面で確認する。
- ゲームコードとセーブデータの保存先を分離し、ElectronでWindows / macOSの操作性を意識する。

## アセットを無駄に読ませない方針

画像・音声・動画は中身を一括読み込みせず、ファイル名と参照コードを先に検索します。変更必要なアセットだけ実在を確認し、フォルダ全体の走査、一括変換、削除、リネームは避けます。

## クレジット消費を増やしやすいNG行動

- 目的を絞らず「全部見て改善して」と頼む。
- ビルドログやテストログの全文を貼る。
- `node_modules`、ビルド成果物、大量アセットを一括調査させる。
- 一度に複数機能の仕様変更と大規模リファクタリングを依頼する。
- 再現手順や守るべき既存仕様を伝えず、推測で調査範囲を広げる。

## 修正後の報告テンプレート

```text
結論: 修正完了 / 要確認
変更ファイル: 最大3〜5件
変更内容: 何をなぜ変えたか
確認結果: 実行したコマンドと成否
未確認: 実機操作など残っている確認
```
